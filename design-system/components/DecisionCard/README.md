# DecisionCard

Карточка решения (подписи): каноническое описание из ядра — что решается, последствия, предусловия, доказательства, кому нельзя.

**Когда.** Зона «Ждёт вашей подписи», страница решения, хроника. Порядок фиксирован: тип и срок → заголовок с глагола → кто просит → почему у вас → доставка → «при да / при нет» → предусловия → доказательства → предложение агента → действия.

**Потребитель передаёт.** Тексты последствий из объявления типа (`approvalSchema`), внешний эффект и обратимость (`yesExternal`), предусловия с текущим состоянием. `risk="high"` для финансовых, юридических и необратимых — доказательства раскрыты до кнопки. `readOnlyReason` — для аудитора и тех, кому решать нельзя: действия скрыты, причина видна. `proposal` — рекомендация агента, явно помечена как предложение.

**Нельзя.** Резюме агента вместо канонического описания; кнопка «да» без последствий; активная кнопка при невыполненном предусловии.

**`compact`** — для колонки 320–360px: последствия столбиком, доказательства одной строкой, только главная и вторая кнопки. **`collapsed`** — вторая и следующие карточки в очереди: тип, заголовок-ссылка, кто просит. **Доказательства** — строки или `{ label, href }`: со ссылкой открывают документ. **После нажатия** (`onPrimary`) кнопки заменяет `footer` с `DecisionStatus`: «Отправляю → Записано в ядре → Исполняется → Исполнено» или отказ ядра словами. Приёмка с непройденным автоматическим критерием не предлагается — в `preconditions` видно, что все автопроверки пройдены.

**Языки.** Каркас карточки — из словаря по локали: «Решение · держит работу», «Почему у вас», «При «да» / При «нет»», «Доказательства», «Предложение агента», кнопки по умолчанию («Согласовать», «Отклонить…», «Открыть историю»). Заголовок, `kind`, `why`, `yes`/`no`, предусловия, `readOnlyReason`, `excluded`, `primary`/`secondary` — данные из ядра и типа работы на языке экрана; компонент их не переводит.
